          How it works

          From alert storm to one approved fix

          Every step reads the same FalkorDB graph: services, hosts, databases, firewall rules, every change and every past incident.

          Alerts arrive

          Prometheus fires; Alertmanager groups them into one incident.

          Walk the graph

          Upward from every alert to what they share: the candidates.

          Gather evidence

          Is the network path open? Who changed what, when? Is it healthy?

          AI double-checks

          An LLM calls the same read-only tools to test the ranking, then explains it.

          A person approves

          The exact undo, its blast radius and rollback. Nothing runs before that.

          Verify, remember

          Alerts must clear. The fix is saved; next time it is offered first.

          Why a graph

          Logs show symptoms. Relationships show causes.

          Ten alerts, one ancestor

          Four services fail because they share one database path. Only the dependency graph shows they share it.

          The path is the proof

          "Is payments allowed to reach the database?" is a graph query over services, hosts and firewall rules, answered in milliseconds.

          Changes and memory live in it

          Every CloudTrail change, every removed rule and every past fix are nodes too, so "what changed?" and "seen before?" are one hop away.

          Proven on real AWS

          We broke a real AWS account by hand.

          Undo-only permissions

          The executor's IAM user can re-add rules, re-attach groups and start instances. It cannot delete or stop anything.

          No AI-written queries

          The model chooses among 12 fixed, reviewed Cypher queries and must give a reason for each call. A validator checks its answer.

          Honest when unsure

          Two causes close together? It says "multiple likely causes" and proposes a fix for each. Not modelled? It says so instead of guessing.
